# Execution and concurrency — decisions

Decision log for [Execution and concurrency](../execution-and-concurrency.md). Entries are append-only: a
replaced entry gets a `Superseded by #M: <clause>.` note appended and is
never rewritten or deleted. The detail doc describes the current design.

- Concurrent default-dir invocations on one repository are supported by giving each run its own detached worktree over one shared store per repository and agent (#1162).
- `agent-loop transport-check` runs one production fetch with the operator's credentials and is required before merging transport changes (#1383).
- SSH transport honours a non-executing subset of `~/.ssh/config` for the literal URL host, refusing rather than escaping any unsafe value, and never runs `ssh -G` (#1380).
- Same-UID live races against `~/.ssh` are left out of scope for the SSH transport (#1371).
- Antigravity tracks quota exhaustion per quota group for the logical run, so a verified exhaustion skips the whole group with no retry instead of retrying each model (#1236).
- The Antigravity `semantic-dedupe` turn reuses the isolated `repair` path (sibling GEMINI lock, no checkout snapshot, strict empty allowlist) with a stdout-only classification contract, so a classifier never creates git metadata in its temporary directory or reads a stale response file (#1472).
- Capture-root retention is an operator setting (default 14 days, 0 disables); pruning never follows symlinks, removes expired roots whole, and deletes the marker and lease last so partial failures are retried (#1572).
- Managed checkouts are compacted under the store flock once they exceed 50 non-kept packs, by one confined exec-free `pack-objects` plus superset verification and snapshot-only deletion, because `git repack` needs exec and `gc.auto=0` stays; failures are logged and never fail the fetch (#1578).
- `import_ref` exports a thin pack excluding destination ref tips the fetched history also holds, skips the pack for a complete existing tip, and gates the CAS on a full-closure check with one full-export fallback, so destination refs are hints and never proof of completeness (#1581).
- A compaction timeout records a private per-store backoff marker beside the store lock (1 h doubling to a 24 h cap, cleared on success or at or below the threshold, failing open on any invalid or too-far-future marker), and timeout and backoff skips log a manual-repack hint (#1580).
- Pack compaction removes any multi-pack-index file, sidecar or chain, without following links, after the threshold and backoff checks and before any pack command, as `git repack -d` does; it never rewrites one, and a removal failure writes no pack and starts no backoff (#1579).
- A parsed long quota reset may optionally be waited out under a run-scoped budget (2 waits, DURATION total) by replaying the exact failed invocation between agent processes, and SIGINT/SIGTERM cancel waits on any thread into a resumable exit-code-3 quota stop (#1601).
- A silent Antigravity attempt is classified as quota exhaustion only from the `RESOURCE_EXHAUSTED` 429 executor line of the single agy CLI log proven new by a pre-spawn inventory under the settings lock and inside the attempt window; any uncertainty keeps the format-failure path (#1604).
- The quota-wait cancel latch persists while any logical run is live and is cleared by a first-run-start hook when the live outermost `workdir_claim_scope` count goes from zero to one with no active wait; a run-lifecycle lock serializes the increment, the hooks and the decrement with other runs' admission (#1609).
- Every agent subprocess resolves the orchestrator's own `agent-loop` through a private import-pinned launcher first on `PATH` (also `AGENT_LOOP_EXECUTABLE`), which is the only run-tests wrapper candidate; receipts carry a diagnostic client tool identity through reserved environment entries, and a mismatched or unidentified client is flagged, never rejected (#1632).
- Untracked test dependencies for per-run worktrees come from an operator-only `--worktree-setup` command run once per shared clone inside `prepare_store`'s lock hold, keyed on the command and `--worktree-setup-key` Git entries at the pinned base SHA, with a private success record that is deleted before every setup attempt and on store (re-)creation; a required setup refuses any tracked modification in the clone or its submodules and never auto-installs from detected manifests (#1650).
- A required `--worktree-setup` also refuses index entries flagged assume-unchanged or skip-worktree (in the clone and its initialized submodules), and with setup configured a store whose index still lists tracked paths is never re-created as stale, so hidden or deleted tracked changes reach the refusal instead of being executed or re-cloned over (#1650).
- With `--worktree-setup`, a store counts as artifact-only (and may be re-created as stale) only when its HEAD is unborn and its index is empty; index entries, a non-empty HEAD tree or any inspection failure keep the store, so staged deletions of every tracked file also reach the setup refusal (#1650).
- A broker request whose `run-tests` client is lost (EOF, reset, a wedged send, or no heartbeat acknowledgement for 30 s through a capability-negotiated ack protocol) is cancelled through its own token in every phase; a running target's whole group is confirmed gone before its lane is released and is journaled as non-evidence, and a client without ack support gets a visible no-test refusal, reversing the earlier rule that a non-reading client never stops its target (#1653).
- `--worktree-setup` kills every process left in the command's group on any exit (success, nonzero or timeout) while the leader is still an unreaped zombie, observed with `waitid(WNOWAIT)`, so a failed attempt's background writer cannot mutate the environment after a retry records success and the group ID is never signalled after it could be reused (#1650).
- On a host without `os.waitid`, `--worktree-setup` refuses before launching instead of falling back to reaping without a group kill, because a reaped leader leaves no safe way to stop the command's surviving background writers (#1650).
- Per-run-worktree dependency remedies are advisory text only, decided from parent-owned config and passed to `run-tests` clients through an advisory environment variable that no classification, outcome, evidence or exit code reads; a poisoned run worktree with a pushed branch gets resume and manual cleanup text but is never removed automatically (#1651).
- The dependency remedy selector is excluded from evidence environment identity, always set explicitly (empty when the condition is false) so an inherited value cannot leak, and mirrored by a parent-chosen broker frame advisory, so the broker path never depends on the agent-side variable (#1651).
- A PR that changes a `--worktree-setup-key` file gets a private environment built by the orchestrator inside its run worktree (links removed without following, then the operator setup command), only behind the opt-in `--worktree-setup-pr-local`; writable worktrees are privatized before their first turn so in-turn installs never write through to the shared clone, setup consumes only committed bytes, and test evidence binds to the concrete environment through a nonce-bearing tracked-digest record, rather than accepting a coder-made replacement of the link (#1652).
- A `--worktree-setup-key` file absent at the base SHA that a successful setup created is exempt from the shared-clone shadow refusal only while its bytes match a separate private, store-identity-bound generated-key ledger that survives failed setups and is deleted on store re-creation; a content-verified generated key the base starts tracking is removed before a checkout that always passes `--no-overwrite-ignore`, and setup has its own operator-only `--worktree-setup-timeout` (default 3600 s) instead of the coder test-command timeout (#1649).

- Structured reports allow confined scratch option-value occurrences for display only; strict receipt evidence and failure authority remain unchanged (#1738).
- Generic equals-form report and temporary-output values preserve their previous classification across display and strict guards; only recognized execution inputs receive general equals-form path extraction (#1738, #1743).

- Report guards and receipt consumers share strict managed-wrapper interpretation; unknown long options never consume option-shaped next tokens, and canonical redacted inner argv correlate equivalent citations without granting scratch display inputs evidence authority (#1768).
