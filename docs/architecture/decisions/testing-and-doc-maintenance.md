# Testing and document maintenance — decisions

Decision log for [Testing and document maintenance](../testing-and-doc-maintenance.md). Entries are append-only: a
replaced entry gets a `Superseded by #M: <clause>.` note appended and is
never rewritten or deleted. The detail doc describes the current design.

- The architecture path names the root of an architecture set, the root plus the `docs/architecture/*.md` files it links to one level deep, so an oversized single document can be split while root-only identities stay unchanged (#1454).
- The `legacy` architecture-impact parser mode keeps the earlier synonym normalization, selected only where stored or historical text is decoded (#916).
- A reviewer's own missing or invalid `architecture_impact.status` is re-asked once with the frozen prompt and session instead of being repaired, because repair cannot supply the reviewer's decision (#1185).
- Architecture-set membership follows a configurable list of detail directories (default `docs/architecture/`) minus history exclusions (default `*/decisions/`, `doc/adr/`, `docs/adr/`) that always win, and the detail-doc index adds a bounded first-sentence summary that is dropped first and never joins an identity; an explicit directory list was chosen over admitting any linked `.md` so default-layout identities stay byte-identical and stray root links never become members, and a deeper membership walk was rejected because it would change the identity (#1499, 2026-10-15).
- A non-array coder `test_observations` is decoded when it is a JSON-array string and otherwise sent to the structured format repair before any citation is dropped; today's #927 drop remains only as the fallback after a failed repair, with a record saying so, and as the default for historical and resume re-parses, because the field is how an evidence-only follow-up reaches the reviewer (#1626, 2026-10-24).
- Source modules get a static line-count guard (6,000-line default) with a per-file allowlist whose ceilings only ratchet down; it is a test under `tests/` so the existing CI command runs it, ceilings may stay above a file that shrank so unrelated fixes need not edit the allowlist, and stale or unnecessary entries fail so the list cannot rot (#1623, 2026-10-25).

- 2026-11-06: The optional PR-review `requirement_evidence` field records semantic signed-source classification. Entries contain requirement_id, role (code, human-only, evidence-only, mixed), request, answered_item_ids and leftover_instructions. The parser checks shape; routing checks surfaced source identity, native target existence and requester ownership. Repair preserves the entire field exactly, including its absence; a real bounded reviewer continuation owns missing classification. Mixed-source prompt and disposition validation use the original signed ID with explicit leftover scope. Classification is separate from native evidence authorization and does not waive live citation validation (#1922).

- 2026-11-06: Reviewer guidance requires classification of every surfaced signed source not acknowledged as resolved, including ordinary code requirements, matching the bounded continuation and human-decision stop. Supersedes the optional guidance in the preceding #1922 entry; the transport field remains optional for acknowledged sources and historical records (#1922).

- Shared prompt context types and reusable guidance move to `prompt_support.py`, keeping role builders in `prompts.py` and the frozen facade surface intact; owner-qualified builder lookups preserve post-import interception without compatibility exports, while prompt text, durable contracts and global size limits stay unchanged (#1931).

- 2026-11-07: Normalize only empty lists and null in requirement_evidence request and leftover_instructions to empty strings without mutating inputs; use indexed field/type diagnostics and explicit prompt types. Format repair permits only this empty-text equivalence when both collections parse, with raw comparison on parser failure. Semantic routing, ownership and native evidence authorization remain unchanged. This supersedes exact raw equality for these two valid empty text fields in the #1922 entry (#1943).
