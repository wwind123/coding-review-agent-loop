# Testing and document maintenance — decisions

Decision log for [Testing and document maintenance](../testing-and-doc-maintenance.md). Entries are append-only: a
replaced entry gets a `Superseded by #M: <clause>.` note appended and is
never rewritten or deleted. The detail doc describes the current design.

- The architecture path names the root of an architecture set, the root plus the `docs/architecture/*.md` files it links to one level deep, so an oversized single document can be split while root-only identities stay unchanged (#1454).
- The `legacy` architecture-impact parser mode keeps the earlier synonym normalization, selected only where stored or historical text is decoded (#916).
- A reviewer's own missing or invalid `architecture_impact.status` is re-asked once with the frozen prompt and session instead of being repaired, because repair cannot supply the reviewer's decision (#1185).
- Architecture-set membership follows a configurable list of detail directories (default `docs/architecture/`) minus history exclusions (default `*/decisions/`, `doc/adr/`, `docs/adr/`) that always win, and the detail-doc index adds a bounded first-sentence summary that is dropped first and never joins an identity; an explicit directory list was chosen over admitting any linked `.md` so default-layout identities stay byte-identical and stray root links never become members, and a deeper membership walk was rejected because it would change the identity (#1499, 2026-10-15).
- A non-array coder `test_observations` is decoded when it is a JSON-array string and otherwise sent to the structured format repair before any citation is dropped; today's #927 drop remains only as the fallback after a failed repair, with a record saying so, and as the default for historical and resume re-parses, because the field is how an evidence-only follow-up reaches the reviewer (#1626, 2026-10-24).
- Source modules get a static line-count guard (6,000-line default) with a per-file allowlist whose ceilings only ratchet down; it is a test under `tests/` so the existing CI command runs it, ceilings may stay above a file that shrank so unrelated fixes need not edit the allowlist, and stale or unnecessary entries fail so the list cannot rot (#1623, 2026-10-25).

- 2026-11-06: The optional PR-review `requirement_evidence` field records semantic signed-source classification. Entries contain requirement_id, role (code, human-only, evidence-only, mixed), request, answered_item_ids and leftover_instructions. The parser checks shape; routing checks surfaced source identity, native target existence and requester ownership. Repair preserves the entire field exactly, including its absence; a real bounded reviewer continuation owns missing classification. Mixed-source prompt and disposition validation use the original signed ID with explicit leftover scope. Classification is separate from native evidence authorization and does not waive live citation validation (#1922).

- 2026-11-06: Reviewer guidance requires classification of every surfaced signed source not acknowledged as resolved, including ordinary code requirements, matching the bounded continuation and human-decision stop. Supersedes the optional guidance in the preceding #1922 entry; the transport field remains optional for acknowledged sources and historical records (#1922).

- Shared prompt context types and reusable guidance move to `prompt_support.py`, keeping role builders in `prompts.py` and the frozen facade surface intact; owner-qualified builder lookups preserve post-import interception without compatibility exports, while prompt text, durable contracts and global size limits stay unchanged (#1931).

- 2026-11-07: Normalize only empty lists and null in requirement_evidence request and leftover_instructions to empty strings without mutating inputs; use indexed field/type diagnostics and explicit prompt types. Format repair permits only this empty-text equivalence when both collections parse, with raw comparison on parser failure. Semantic routing, ownership and native evidence authorization remain unchanged. This supersedes exact raw equality for these two valid empty text fields in the #1922 entry (#1943).

- 2026-11-08: Final integration records per-family admission ownership and historical replay consequences, with recursive reader inventory review and repeated lifecycle restart regressions; existing author sets and root invariants remain unchanged (#1976, #1959).

- 2026-11-08: Reviewer diff instructions (command policy, sandboxed inspect forms, Antigravity single-shot header) name `origin/<base>...HEAD` through `review_diff.py`, because the shared store's local base branch may be missing, checked out elsewhere or lagging, while every base fetch writes the remote-tracking ref; earlier Antigravity headers stay recognized for recovery. PR amendment emitters evaluate one admitted record set (#1977, #1986, #1989).

- 2026-11-22: A deterministic validation failure of a structured response is re-asked to the same agent (same model, its own session when available) with the sanitized validator message and a resend-only instruction, at most twice per turn; this replaces the cross-model repair pass, content preservation and the separate omission, judgement, evidence, contract and matrix replay slots, because a preservation failure was terminal more often than repair recovered and the original agent can fix its own response in one turn. Mechanical normalization moves to `response_normalization.py` and always runs; a coder re-ask is head-guarded and keeps the active evidence acquisition (replaced only by a fresh-evidence re-ask); `--repair-*` flags become deprecated no-ops for one release; the repair modules are deleted in stage 2. Supersedes the repair-routing clauses of the #1185 and #1626 entries (#2066, #2091).

- 2026-11-23: Live validators drop prior-item dispositions for IDs outside the carried set, before parsing and with no count or length bound, and record them on the result, in an optional spillable round-metadata field and as a visible note. They no longer raise the unknown-disposition error, because such a disposition has nothing to apply to, and rejecting it never recovered a lost item while repeated planners stalled whole runs. The accepted text is canonicalized at the acceptance boundary so downstream reparsers agree. Missing carried dispositions keep their existing semantics. Supersedes the #862/#872 fail-closed rule for an incomplete ledger and the history-proven strip as the only remedy (#2100).

- 2026-11-23: Lossless value-shape slips (singleton-list strings, null or lone-string lists, closed-enum case and separator variants, empty architecture/allocation defaults, digit-string integers, PR-finding text aliases) are normalized inside the parsers with a log line instead of costing a re-ask, while identifiers, signed labels, envelopes and evidence citations stay exact through a separate strict helper. A case/separator fold of a declared architecture status (`Unchanged`) now reads as that status instead of degrading to `undetermined`, because the fold is lossless; real synonyms keep the degrade handling. Supersedes the "`Unchanged` is never read as `unchanged`" rule of the #925 near-miss design (#2109).

- 2026-11-23: Harmless extras are dropped or aliased in the parsers instead of being rejected. Unknown string-valued keys at opted-in agent-response sites are dropped with a warning; protected or authority-looking names and non-string values still reject, and the trust-boundary parsers stay strict. A plan review's `blocking_items`/`same_pr_followups` are renamed so findings survive. Disposition `reason`/`rationale` become `note`. Dispositions for unsurfaced requirement IDs are dropped before blocked-state and conflict decisions. `addressed_ids` is derived from dispositions. Fully equal duplicates collapse. Unlisted notes and unknown coder item IDs are dropped and recorded. Historical decoders never re-apply a live, context-dependent check. Missing coverage, conflicting duplicates and protected keys still reject. Supersedes the unknown-ID rejection in the #1388 coder validator and the exact-key rejection at the listed sites (#2114).

- 2026-11-23: A same-agent re-ask that cannot resume a session quotes a bounded, sanitized copy of the rejected response, because a session-less re-ask (Codex, Antigravity) is otherwise a blind full redo that risks the same slip or different judgements; a session-backed re-ask is unchanged so the response is never duplicated. The listed risk-matrix applicability/operation and `requirement_evidence` key/role rejections name their index and allowed values; exception types and shape-check classifications are unchanged. Collecting every shape error in one pass was declined as not simple (#2128, #2115).

- 2026-11-24: Stage 2 of the re-ask rule deletes the now-unreachable `repair.py`, `repair_preservation.py`, `agents/format_repair.py` and `shape_check_audit.py`, their tests, the inline `# shape-check:` annotations in the protocol parser modules (comment-only), the repair-only acknowledgement pin helpers, the unused `use_repair` and repair-only item-ID parameters of the validated turn, and the test-only stand-ins for the retired repair seams. The near-miss canonicalization tests move to `tests/test_response_normalization.py`, and a static test keeps `repair_backend` confined to the deprecated no-op flag handling. The shape-check audit is not replaced: with no repair pass, an error's repairability classification has no consumer. Historical repair failure categories and drop-rule names stay parseable (#2092, #2066).
